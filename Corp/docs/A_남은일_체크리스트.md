## 2. A 설계에서 이번에 새로 발견한 문제 (수집 전 결정 필요)

- [ ] **B-1. 긴축 변수 Tight_q가 사전기간에도 움직인다 `[확인]`**
  `rates.csv` 기준 2019Q1 말 1.75%, 2021Q2 말 0.50%이므로 Tight = 분기말 금리 − 0.50 은 2019Q1 +1.25, 2019Q4 +0.75, 2020Q1 +0.25, 2020Q2~2021Q2 0, 2022 이후 증가다. 즉 **인하기(2019~2020)에 이미 양수**여서, 하나의 β가 인하와 인상을 한 직선으로 묶는다(대칭 가정). 결과를 보기 전에 정해야 한다.
  선택지(`[제안]`): (i) v1과 같은 Post 더미(2022 이후, 2021 전환) (ii) max(0, 금리−0.50)처럼 인상분만 (iii) 이벤트스터디(분기별 계수)를 주 그림으로 두고 연속형은 보조. 어느 쪽이든 변경 기록에 "결과를 보기 전"으로 적는다.
- [ ] **B-2. 연결/별도 혼재 63곳**(A2 적용 후 1,321곳 중) `[확인]`
  2019 사업보고서와 2021 반기보고서의 재무제표 구분이 다르다(연결→별도 21 / 별도→연결 43 — 전체 통과 기준 64곳 중 A2 적용 후 63곳). 문서의 "한 기업 안에서 기준을 섞지 않는다"를 적용할 규칙이 없다. 원인은 확인하지 못했다(연결 작성 의무 시작 등은 가설). 규칙 후보: ① 기업별로 하나로 고정(어느 쪽?) ② 혼재 기업은 별도 표시하고 강건성에서 제외.
- [ ] **B-3. 수집할 보고서 범위**: 문서는 2018~2024. A11(리스 기준, 창 시작 2019Q4)을 따르면 TTM에 2019 보고서만 필요하고 2018은 불필요하다 `[제안]`. 2018 포함 시 기업당 4개, 약 5,300건이 늘어난다(1,321×4). 범위를 정해야 요청 수가 정해진다.
- [ ] **B-4. 기업별 재무제표 구분 기억**: 별도(OFS)만 있는 기업(통과 중 약 285곳)은 매 보고서마다 연결을 먼저 조회하면 요청이 약 2배로 늘어난다. 선별 결과의 구분을 재사용하도록 수집 스크립트를 설계 `[제안]`.
- [ ] **B-5. 업종 셀 크기**: A2 적용 후 업종 중분류별 기업 수에서 5곳 미만은 12번(1곳)·16번(4곳)·18번(2곳), 10곳 미만은 12·15·16·18·19·32번. 업종×분기 고정효과 안에서는 한 업종에 1곳이면 β 추정에 기여하지 않는다. A5(최소 기업 수)가 필요.
- [ ] **B-6. 지주회사 표시 21곳**(스팩 0곳): 사전 고정 문서 3절의 "지주회사·스팩·금융업 제외"는 이름 기반 자동 표시 후 **수동 검토**로 정하게 돼 있다. 21곳 수동 검토 필요.
