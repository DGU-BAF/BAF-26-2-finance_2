# scripts/ — 노트북에서 .py 만들기

## 한 줄 규칙

**노트북(.ipynb)이 원본이고, 같은 이름의 .py는 노트북에서 자동 생성한 파일입니다. `.py`를 직접 고치지 마세요.**

## 왜 이렇게 하나

- 사람이 읽는 것은 노트북입니다(마크다운 설명 + 코드 + 저장된 출력).
- 다른 스크립트가 경로로 불러오거나 명령줄로 실행하는 것은 `.py`입니다(예: `10_차입_전기간.py`가 `06_노출도E_만들기.py`를 불러옴).
- 코드를 노트북에만 쓰고 `.py`를 만들어 내면 **코드가 한 벌**이라 둘이 어긋나지 않습니다.

## 사용법

```
python -X utf8 scripts/노트북에서_py_만들기.py                 # src 아래 '생성_py'가 있는 모든 노트북에서 .py 생성
python -X utf8 scripts/노트북에서_py_만들기.py 노트북경로.ipynb   # 하나만
python -X utf8 scripts/노트북에서_py_만들기.py --검사            # 쓰지 않고 노트북과 .py가 같은지만 확인 (어긋나면 종료 코드 1)
```

## 노트북을 쓸 때 지킬 약속

| 약속 | 내용 |
|---|---|
| 노트북 메타데이터 `생성_py` | 만들 .py 파일 이름(노트북과 같은 폴더). 없으면 변환 대상이 아님 |
| 코드 셀 태그 `노트북전용` | .py에 넣지 않음. 설명용 예시, 결과 표시, 실행 셀(`main()` 호출 등) |
| 마크다운 셀 태그 `py전용_코드` | ```` ```python ```` 블록의 코드를 .py에만 넣음. 보통 `if __name__ == "__main__": main()`. 노트북에서는 `__name__`이 항상 `"__main__"`이라 일반 코드 셀로 두면 열 때마다 실행되기 때문 |
| 마크다운 셀의 첫 제목 줄 | .py에 구분선 주석으로 들어감 |
| `__file__` | 노트북에는 없으므로 `try: HERE = Path(__file__)... except NameError: HERE = Path.cwd()` 형태로 씀 |
| 인증키 | 노트북에 절대 쓰지 않음. 환경변수에서만 읽음. 출력에 키가 나오지 않게 확인 |

## 바꾼 뒤 확인하는 법 (시범 때 쓴 방식)

1. 결과 파일(csv)의 해시를 저장해 둔다.
2. 노트북을 다시 실행한다 → 결과 해시가 같은지 확인.
3. `노트북에서_py_만들기.py`로 .py를 만들고 실행한다 → 결과 해시가 같은지, 함수 정의(`ast`)가 원본과 같은지 확인.

## 예외

`src/01_파일럿/config.py`, `dart_api.py`는 다른 코드가 `import`하는 이름이라 영문 .py를 직접 씁니다(설명은 `00_공통부품_설명.ipynb`). 01_파일럿~04_A2_코넥스_선별의 기존 노트북 8개는 예전 방식(.py를 노트북으로 한 번 바꾼 것)이라 이 변환 대상이 아닙니다.

## 알아둘 점

- **키가 필요한 스크립트(04·05·06·07-04)**: 노트북은 키 없이 `--dry-run`만 실행한다. `--summary-only`는 수집로그의 출처 칸(api→cache)을 다시 써서 원래 기록이 바뀌므로 노트북에서 쓰지 않는다.
- **명령줄 옵션이 있는 스크립트**: 노트북 실행 셀에서 `sys.argv = [...]`로 같은 옵션을 준다(`11_모듈`은 모듈 이름).
- **`Path(__file__).resolve().parents[k]`**: 노트북에서는 `HERE.parents[k-1]`로 바뀐다(`HERE`가 이미 파일이 있는 폴더라서 한 단계 낮다). 변환 도구가 이렇게 처리한다.
- **`07_차입계정_이름확인`의 빈도표 2개**: 같은 빈도끼리의 줄 순서가 실행마다 달라질 수 있다(기업 코드 집합 순회). 내용은 같다. 결과 해시를 비교할 때는 정렬한 뒤 비교한다.
- **재실행 시간(이 컴퓨터, 2026-11-05)**: `06_본수집` 약 6분(dry-run), `11_모듈` 약 5분 30초, `07_계정확보/01` 약 1분 30초, 나머지는 대부분 1분 이내.
