# Corp — 기업 단위(A) 분석

업종 단위(v1)와 같은 질문("금리 인상 전 단기차입 비중이 높았던 기업일수록 인상 후 이자보상비율(ICR)이 더 나빠졌는가")을 OpenDART 재무제표로 **기업 × 분기** 단위에서 묻는 트랙이다.

**현재 상태 (2026-11-05)** — 본수집(1,321곳, 보고서 27개)·노출도 E·ICR 패널·첫 회귀·사후 탐색 3라운드까지 실행했다. 결과는 모두 **탐색적**이며 규칙 대부분은 **팀 확정 전**이다. 요약은 `docs/A_팀전달_한장요약_11-05.html`, 전체 경위는 `docs/A_팀전달_전체보고서_11-05.html`.

## 가장 먼저 알아둘 규칙 — 노트북이 원본

`src/07_계정확보`와 `src/08_분석`, 그리고 `03~06` 단계의 스크립트는 **한글 이름 노트북(.ipynb)이 원본**이고, 같은 이름의 `.py`는 노트북에서 **자동 생성**한 파일이다. `.py`를 직접 고치지 않는다(다음 변환 때 덮어써진다). 손으로 쓴 옛 `.py`는 각 폴더의 `원본_스크립트/`에 보관했다. 자세한 약속과 사용법: `scripts/README.md`.

```
python -X utf8 scripts/노트북에서_py_만들기.py            # 노트북 → .py 생성
python -X utf8 scripts/노트북에서_py_만들기.py --검사     # 노트북과 .py가 같은지 확인
```

예외: `src/01_파일럿/config.py`, `dart_api.py`는 다른 코드가 import하는 이름이라 영문 `.py`를 직접 쓴다(설명은 `00_공통부품_설명.ipynb`). `08_분석/lib.py`는 `00_공통함수.ipynb`에서 생성된다.

## 폴더 구조
```
Corp/
├─ README.md
├─ data/raw/            DART 원본 응답(corpCode.zip, company/, fs/, xbrl_test/)과 KIND 원자료. 수정 금지, git 제외
├─ outputs/             단계별 결과표 (아래 표)
├─ docs/                모든 HTML·설명 문서는 여기에만 둔다
├─ scripts/             노트북에서 .py 만들기 도구와 규칙(README.md)
├─ archive/             11/2 시점 폴더 압축 백업(git 제외)
├─ 논문/                 선행연구 PDF
└─ src/                 단계별 코드 (아래 표)
```

- 같은 폴더 안에서는 번호 순서로 실행한다. 단, 08에서 `10_차입_전기간`은 `11_모듈`(M4)이 쓰므로 `11`보다 먼저, `12_통합정리`는 `11` 다음이다.
- 키가 필요한 노트북에도 **키를 적지 않는다**. 키는 본인 PowerShell 창에서 `$env:DART_API_KEY = "..."`로만 설정한다.
- 노트북은 자기 폴더에서 실행한다(`HERE`를 현재 폴더로 잡는다). 폴더 이름이 `04_본수집`(outputs)처럼 단계 번호와 다른 곳은 옛 번호가 코드에 남은 것이다.

## 알아둘 것
- **인증키는 어디에도 저장하지 않는다.** 본인 PowerShell 창에서 설정하고 같은 창에서 실행한다. 키를 채팅·파일·깃에 적지 않는다.
- 01·02 파일럿 노트북에는 안전 스위치(`ALLOW_API`, `RUN_COLLECTION`)가 `False`로 되어 있다. `True`로 바꾸면 저장 안 된 것만 요청한다.
- 수집 스크립트의 `--summary-only`는 수집로그의 출처 칸(api→cache)을 다시 써서 원래 기록이 바뀐다. 그래서 04~06 노트북은 요청 수만 세는 `--dry-run`만 실행한다.
- 임계값·기준(허용오차 0.5%, M≥50%, 신호 기준 등)은 대부분 임의로 정한 값이며 공식·학술 기준이 아니다.
- 열린 결정(팀 확인 필요): ICR 분모 정의(금융비용 vs 업종 v1 정의), E·표본 규칙, 논문 방향, 11/12 발표에 A 결과를 쓸지. 상세는 `docs/A_사전고정_문서_초안.md`.
