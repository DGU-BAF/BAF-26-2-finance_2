## 파일 정리 이력 (9/30)

- 팀원 노트북 이름 규칙("N_설명.ipynb")에 맞춰 전체 11개 파일을 1~11번으로 재정렬(기존 "01 vs 1" 이중번호·오타 "안전성"→"안정성" 수정 포함).
- **`긴축기_재무_원자재_병합검증_EDA.ipynb` + `평시_재무_원자재_병합검증_EDA.ipynb` → `9_병합검증_긴축기평시.ipynb`로 통합**(둘 다 같은 코드를 대상 파일만 바꿔 돌린 것이라 합쳐도 정보 손실 없음, 원본 2개는 삭제).
- `1_안정성_원자료검증.ipynb`↔`2_안정성_전체EDA.ipynb`, `3_수익성_원자료검증.ipynb`↔`4_수익성_전체EDA.ipynb`는 **합치지 않음** — 서로 다른 코드로 같은 결론(차입의존도=자본총계 등)에 독립적으로 도달한 교차검증이라 합치면 그 증거가 사라짐.

**모든 파일 내부 경로 수정 완료(9/30)**: 1~8번 전부 팀원 개인 PC 절대경로(팀원 개인 PC 절대경로) 또는 우리 실제 폴더구조와 다른 상대경로(`../data/raw/...`)를 갖고 있었음 — 전부 `2. EDA/` 폴더에서 실행 가능한 올바른 상대경로로 교체, 실제 파일 존재 확인까지 완료. **7번(기준금리)만 CSV 자체가 바뀌어서(2018-04-20 행 삭제) 결과를 초기화함 — 재실행 필요.** 나머지는 데이터 안 바뀌어서 기존 결과 그대로 유효.

## 7·8번 — 병합 정확성 검증(긴축기+평시), 9/30 완료 경위

원래 별도 두 노트북이었으나 `9_병합검증_긴축기평시.ipynb`로 통합.

**평시 트랙**: 5개 검사(키구조/직접병합값/파생변수 재계산/원자료 전체재구성/이상치 원자료대조) 전부 통과, 코드+출력 근거 있음(허구 없음). IQR 이상치 78건을 원자료와 개별 대조해서 전부 "원자료일치=True"로 확인 — 병합 때문에 생긴 이상값은 0건. 덤으로 확인된 것: 사전노출도·현금여력 기준 산업별 이질성 — 주조·목재·인쇄·조선(노출도 높고 현금여력 낮음, 취약군) vs 담배·반도체·디스플레이·통신기기(노출도 낮고 현금여력 높음). 반도체 2017=4759.9, 전지 2016=-2655.1 등 기존 확인값과 정확히 일치.

**긴축기 트랙**: 첫 실행에서 최종판정 5개 중 2개(파생변수, 전체재구성)가 실제로 "실패"로 나옴. 원인 규명: 검증 노트북의 자동추론 로직이 "Post=0인 연도 전부 = 사전기간"이라고 가정했는데, 긴축기는 사전기간(2018~2020, 3개년)과 Post=0 연도(2018~2021, 4개년) 사이에 **2021년이라는 갭 연도**가 있어서 이 가정이 깨짐(평시는 이 갭이 없어서 우연히 맞았던 것). **병합 자체의 오류는 아니었음** — 사전기간을 2018~2020으로 명시적으로 고정하도록 코드 수정 후 재실행, 5/5 전부 통과로 확정.

**히트맵 해석 중 실제로 틀렸던 부분도 수정함**: "통신기기·담배가 분석기간 내내 높은 ICR 유지"라던 원래 해석이 틀림 — **통신기기와 반도체 둘 다 2018~2022엔 ICR이 높다가 2023년에만 가장 낮은 쪽으로 뒤집힘**. 이건 2022~23년 반도체 다운턴이 실제 데이터에 반영된 것으로 해석되며, 15번(반도체 통제변수) 필요성을 뒷받침하는 추가 근거임.

## 9·10번 — 다중공선성·ICR변환, 9/30 완료 경위

**9번(다중공선성) 결론**: 노출도·현금여력·원자재충격 VIF 전부 5 미만(1.0~2.9) — **통과, 문제없음**. 노출도-현금여력 레벨 상관은 -0.53~-0.63으로 존재하지만(경제적으로 타당: 단기부채 많을수록 유동성 여력 낮음), 실제 회귀에 들어가는 Post 상호작용항 단계에서는 VIF가 안전권. `shock_baseline`과 `shock_extended`는 사실상 동일 변수(r≈1.0) — 회귀에 하나만 투입 권장.

**10번(ICR 변환) 결론**: 원자료 왜도가 심각(긴축기 +5.14, 평시 +7.91)해서 무변환은 부적절. **예상 밖 발견**: winsorize는 왜도를 절반 완화하되 방향(+) 유지, **asinh는 왜도 절대값은 더 줄이지만 부호가 음(-)으로 뒤집힘**(큰 양수 이상치를 너무 눌러서 음수 ICR 쪽 꼬리가 상대적으로 부각됨). 어느 쪽도 완벽하지 않아 **최종 선택은 이 EDA만으론 확정 안 하고, 세 버전으로 본회귀를 돌려 계수 민감도를 비교한 뒤 결정하기로 보류**.

## 11·12번 — 반도체5개 Δ이상치·ICR분해, 9/30 완료 경위

**11번 결론**: 반도체5개 그룹이 **2017년(평시, 상위 62.5%)뿐 아니라 긴축기 전체(2019 하위 62.5%, 2020~21 상위 편중, 2022 하위 37.5%)에 걸쳐 지속적으로 극단값에 몰림** — 단발성 사건이 아니라 반도체 고유 경기순환의 구조적 영향. leave-group-out 차이도 평시 2017(+409.53, 압도적)과 긴축기 2022(-135.64)·2023(-133.39)에서 크게 나타나, **반도체 다운턴이 긴축기 후반 계수를 오염시킬 수 있다는 우려가 실제 숫자로 뒷받침됨.**

**12번 결론**: 대부분 영업이익(분자) 요인이 ICR 변화를 주도하지만, **2019·2022~2023년엔 이자비용(분모) 요인도 상당히 커짐** — 특히 반도체 2023년은 이자비용 증가율(+139.8%)이 영업이익 감소율(-131.3%)만큼 크다. 긴축기 후반부에 금리효과가 실제로 이자비용에 반영되기 시작했을 가능성 — **반도체 통제변수 필요성의 추가 근거.**

## 15번 — 반도체 통제변수 적용방식, 설계원칙 확정

**"전 업종 공통값" 방식은 성립 불가능함을 확인**: 모든 업종에 같은 값을 넣으면 연도 고정효과와 완전히 겹쳐서(선형종속) 자동으로 흡수되어 계수가 안 나옴 — 원자재값을 가중치 없이 못 쓰는 것과 동일한 이유.

**유일하게 성립하는 방식**:
```
반도체통제_it = 반도체더미_i × 반도체사이클_t
(반도체더미_i = 1 if i∈{반도체,디스플레이,컴퓨터,통신기기,전지}, else 0)
```
이는 사전추세검정에서 이미 검증된 "반도체더미×연도" 방식과 같은 구조이며, 연도더미 대신 `8_반도체사이클_통제변수설계.ipynb`의 연속형 지표로 대체해 파라미터를 절약하는 버전.

**주의**: 이 "5개 업종"은 ISTANS 공식분류(I31 고위기술산업군, 9개)의 부분집합이며, 2017년 ICR 급등 패턴을 보고 사후에 고른 것이라 임의기준 위험이 있음(검토8원칙 4번). 최종 결정 전 I31 전체(9개)로도 강건성 비교 필요.

**남은 것**: 후보 A(출하증가율 단독)/B(출하+재고+가동률)/C(PCA PC1) 중 최종 선택 — 14번(병합+회귀) 끝나야 실제 민감도 비교 가능.

## 16번 — 환율(FX) 노출도, 설계만 완료·실행은 보류

**설계**:
```
수출비중_i = 수출유발액_i (381개 IO코드 → 40업종, 기존 W행렬로 집계) / 총산출액_i
FX노출도_it = 수출비중_i × Δ환율_t
```
- 수출비중 재료는 이미 확보됨: `data/원자재/투입산출표_생산자가격_기본부문_2019년연장표.xlsx`의 "최종수요항목별 생산유발액" 시트, 컬럼코드 9140=수출.
- 환율(원/달러 연평균) 데이터 확보 완료: `data/환율/원달러_환율_연평균_1990_2025.csv` (1990~2025, 결측 0, 1998/2008/2022 등 알려진 사건과 부합 확인됨).
- **실제 계산·병합은 7~14번 끝날 때까지 보류.**
